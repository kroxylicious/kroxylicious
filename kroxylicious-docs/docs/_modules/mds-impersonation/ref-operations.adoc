= Operation and limitations

[role="_abstract"]
Each new broker connection obtains a token for its own mapped client identity.
The filter holds the first Kafka request until MDS and upstream SASL authentication succeed.
No token cache is shared between client connections or users.

[cols="1,2"]
|===
|Setting |Meaning
|`mdsUrl` |Full HTTPS impersonation endpoint. Redirects are rejected. Use an HA endpoint if required.
|`mdsTls` |Proxy identity and MDS server trust. PEM and key stores use standard TLS configuration. Insecure trust and dynamic credential suppliers are rejected.
|`requestTimeout` |MDS connect/request timeout; defaults to `5s`, maximum `1m`. Keep it below the proxy filter timeout. HTTP responses are limited to 64 KiB.
|`expiryMargin` |Safety margin before JWT expiry or a shorter broker session lifetime; defaults to `5s`, range `1s` to `1m`.
|===

At the next request after the expiry deadline, the filter closes the connection without forwarding that request.
Clients reconnect and obtain fresh tokens through the proxy.
Idle connections are not closed proactively, and in-flight requests can fail when a connection closes.
Configure normal Kafka retries and allow for consumer rebalances during reconnects.
The filter does not implement transparent KIP-368 reauthentication or promise uninterrupted TCP sessions on failover.
Keep MDS, broker and proxy clocks synchronized.

The proxy passes each certificate-derived user name to MDS, which enforces its impersonation super-user and protected-user settings.
Missing certificates, anonymous mappings, blank names or names containing control characters, downstream SASL requests, MDS errors and upstream authentication errors close the connection.
The filter logs closure at INFO with the session ID but never logs tokens or remote response bodies.
Use MDS audit logs to diagnose denied impersonation and broker logs to diagnose token validation and RBAC denials.
Disable protocol/frame logging around authentication because such messages contain bearer tokens.
No filter-specific metrics are introduced in this draft.

Certificate files are loaded when the filter initializes. Restart or reconfigure the proxy after rotating its MDS identity.
Every Metadata and FindCoordinator connection must still resolve and route through the appropriate proxy endpoints.
Endpoint rewriting is provided by the proxy runtime, and this filter authenticates each resulting connection independently.

The module includes an opt-in Docker Compose environment using Confluent Platform 8.3.1 with real MDS and one KRaft broker/controller.
Integration tests cover certificate-derived RBAC access and denial, MDS rejection of a protected user, two-consumer rebalance, and delivery across token expiry and reconnects.
For reproduction, use the module's `integration/README.md` in the source repository.
Multi-broker coordinator and leader changes, RBAC audit log identity, VRF routing, gateway failover, and a complete Operator deployment remain unvalidated.
The filter API does not expose the upstream TLS or routing configuration; ensure that the virtual cluster uses verified broker TLS and direct routing.
