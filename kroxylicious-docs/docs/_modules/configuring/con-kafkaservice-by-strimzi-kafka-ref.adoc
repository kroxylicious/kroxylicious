= Configuration for Kafka clusters managed by Strimzi

[role="_abstract"]
If the proxied Kafka cluster is managed by the {StrimziSite} operator and runs in the same Kubernetes cluster as the proxy, a `KafkaService` can reference the Strimzi `Kafka` resource directly instead of specifying `bootstrapServers`.
The Kroxylicious Operator then discovers the bootstrap address of the cluster from the status of the `Kafka` resource, and can optionally trust the cluster CA certificate that Strimzi generates.
This removes the need to copy the bootstrap address into the `KafkaService`, and the need to extract the Strimzi cluster CA certificate into a `ConfigMap` or `Secret` for the proxy to trust.

.Prerequisites

* Strimzi 0.49.0 or later is installed in the Kubernetes cluster. The Kroxylicious Operator reads the `v1` version of the `kafka.strimzi.io` API.
* The `Kafka` resource is in a namespace that the Kroxylicious Operator watches.
* The `Kafka` resource declares a listener that the proxy can reach from its pods. An `internal` listener is usually appropriate when the proxy runs in the same Kubernetes cluster as the Kafka cluster.

This example shows a `KafkaService` that references a Strimzi `Kafka` resource named `my-cluster` and connects to its `tls` listener, trusting the Strimzi cluster CA.

.Example `KafkaService` referencing a Strimzi `Kafka` resource
[source,yaml]
----
kind: KafkaService
apiVersion: kroxylicious.io/v1alpha1
metadata:
  name: my-cluster
  namespace: my-proxy
spec:
  strimziKafkaRef:
    name: my-cluster
    listenerName: tls
    trustStrimziCaCertificate: true
  nodeIdRanges:
    - name: brokers
      start: 0
      end: 2
  # ...
----
where:

* `strimziKafkaRef` references the Strimzi `Kafka` resource that declares the cluster to be proxied. Specify either `strimziKafkaRef` or `bootstrapServers` in a `KafkaService`, but not both.
** `name` is the name of the `Kafka` resource.
** `namespace` is optional and identifies the namespace of the `Kafka` resource. If omitted, the `Kafka` resource is expected to be in the same namespace as the `KafkaService`. The namespace must be watched by the operator.
** `listenerName` is the name of a listener declared in `spec.kafka.listeners` of the `Kafka` resource. The operator uses the bootstrap address that Strimzi reports for this listener in `status.listeners` of the `Kafka` resource.
** `trustStrimziCaCertificate` is optional and defaults to `false`. When `true`, the proxy trusts the cluster CA certificate generated by Strimzi. For details, see xref:con-kafkaservice-strimzi-ca-trust-{context}[Trusting the Strimzi cluster CA certificate].
** `kind` and `group` are optional and default to `Kafka` and `kafka.strimzi.io`. These are the only supported values.
* `nodeIdRanges` declares the IDs of all broker nodes in the Kafka cluster. The ranges must cover the node IDs assigned to the Strimzi cluster brokers—for example, through `KafkaNodePool` resources. Currently, the operator does not derive node IDs from Strimzi resources.

After the operator resolves the reference, it records the discovered bootstrap address in `status.bootstrapServers` of the `KafkaService`.
The operator watches the `Kafka` resource, so if Strimzi changes the bootstrap address of the listener, the operator updates the proxy configuration accordingly.

[id='con-kafkaservice-strimzi-ca-trust-{context}']
== Trusting the Strimzi cluster CA certificate

Strimzi signs the TLS server certificates of the brokers with a cluster CA, and stores the CA certificate in a `Secret` named `<kafka-name>-cluster-ca-cert` in the namespace of the `Kafka` resource.
When `trustStrimziCaCertificate` is `true`, the operator configures the proxy to trust the `ca.crt` entry of that `Secret` when connecting to the cluster over TLS.
The listener named by `listenerName` must have `tls: true` in the `Kafka` resource.

The operator watches the `Secret`, so when Strimzi renews the cluster CA the proxy is reconfigured with the new certificate.

If `spec.tls.trustAnchorRef` is also specified in the `KafkaService`, it takes precedence and `trustStrimziCaCertificate` is ignored.

IMPORTANT: Setting `trustStrimziCaCertificate` to `true` delegates trust decisions for the proxy-to-cluster connection to the Strimzi operator. Anyone with write access to the `<kafka-name>-cluster-ca-cert` `Secret` can control which certificates the proxy trusts.

Other TLS settings, such as `spec.tls.certificateRef` for client authentication, `spec.tls.protocols`, and `spec.tls.cipherSuites`, can be combined with `strimziKafkaRef` in the usual way.

== Checking the status of a `KafkaService` referencing a Strimzi `Kafka` resource

The operator reports the outcome of resolving `strimziKafkaRef` in the `ResolvedRefs` condition of the `KafkaService` status.

.Example `KafkaService` status after the Strimzi `Kafka` resource is resolved
[source,yaml]
----
kind: KafkaService
apiVersion: kroxylicious.io/v1alpha1
metadata:
  # ...
  generation: 1
spec:
  strimziKafkaRef:
    name: my-cluster
    listenerName: tls
    trustStrimziCaCertificate: true
  # ...
status:
  observedGeneration: 1
  bootstrapServers: my-cluster-kafka-bootstrap.my-proxy.svc:9093
  tls:
    trustAnchorRef:
      kind: Secret
      name: my-cluster-cluster-ca-cert
      key: ca.crt
      storeType: PEM
  conditions:
    - type: ResolvedRefs
      status: "True"
      observedGeneration: 1
----
where:

* `status.bootstrapServers` is the bootstrap address discovered from the `Kafka` resource.
* `status.tls.trustAnchorRef` shows the trust anchor the proxy uses. When `trustStrimziCaCertificate` is `true`, it identifies the Strimzi cluster CA `Secret`.

If the `ResolvedRefs` condition has a `status` of `False`, the `reason` and `message` of the condition describe the problem.

.Reasons for a `False` `ResolvedRefs` condition
[cols="1,2"]
|===
|Reason |Cause

|`ReferencedResourcesNotFound`
|The `Kafka` custom resource definition is not installed, so the Strimzi operator is probably not installed; the `Kafka` resource does not exist in the expected namespace; the namespace is not watched by the operator; or, when `trustStrimziCaCertificate` is `true`, the `<kafka-name>-cluster-ca-cert` `Secret` does not exist.

|`ReferencedGroupKindNotSupported`
|`kind` or `group` of the `strimziKafkaRef` has a value other than `Kafka` and `kafka.strimzi.io`.

|`InvalidReferencedResource`
|The `Kafka` resource does not declare a listener with the name given in `listenerName`.

|`ReferencedResourceNotReconciled`
|Strimzi has not yet reported the listener in the status of the `Kafka` resource. This is normal while the Kafka cluster is starting. The operator reconciles the `KafkaService` again when the `Kafka` status changes.
|===

To inspect the condition, describe the `KafkaService`:

[source,shell]
----
kubectl describe kafkaservice my-cluster -n my-proxy
----
